# 闭源组件说明：RLY/0 Core

本文档说明公开仓库（RLY/0 Hub，LGPL-3.0）与闭源组件 **RLY/0 Core**（`rly0-core`）之间的边界，
以及为什么这种组合方式符合 LGPL-3.0 的要求。

## 职责边界

| 功能 | 所在仓库 | 说明 |
| --- | --- | --- |
| Codex Desktop 内多 Harness 宿主、界面框架、设置页壳层 | 公开仓库（本仓库，LGPL-3.0） | 继承自 CodexHost |
| 仪表盘、线程管理、MCP / Skills 管理、维护工具、外观设置 | 公开仓库 | 不依赖 rly0-core，无它也能完整运行 |
| 账号管理的界面（列表、按钮、对话框） | 公开仓库 | 界面代码；实际的多账号保存/切换等操作转发给 rly0-core |
| 多账号保存 / 切换 / 改名 / 删除 | **rly0-core（闭源）** | 通过 JSON-RPC 暴露 `accounts/*` 方法 |
| 额度读取（5 小时 / 每周窗口） | **rly0-core（闭源）** | `accounts/usage`、`accounts/usageAll` |
| 中转站（relay）配置的增删改查、测速测试 | **rly0-core（闭源）** | `relay/*` 方法 |
| 本地代理（按模型名路由到中转站） | **rly0-core（闭源）** | `proxy/start` / `proxy/stop` / `proxy/status`，只监听 `127.0.0.1` |

简单地说：**公开仓库负责“看得见的界面”和不涉及多账号/中转的所有其他功能；rly0-core 负责“多账号与中转”背后的实际业务逻辑与敏感数据处理。**

## 接口：stdio 上的 JSON-RPC

- rly0-core 编译为一个**独立的可执行程序**，由公开仓库的 Host 进程在需要时启动为**子进程**。
- 两者之间**只通过标准输入/输出（stdio）传递按行分隔的 JSON-RPC 2.0 消息**进行通信，没有任何函数调用、
  头文件引用、静态链接或动态链接关系。
- 典型方法包括 `core/hello`、`accounts/list`、`accounts/switch`、`accounts/usage`、`relay/list`、
  `relay/add`、`proxy/start` 等；具体字段以两者实际实现为准，此处不重复列出接口细节。
- 公开仓库中调用这些方法的代码，是通过一个**抽象客户端接口**（例如 `RendererRly0AccountClient`）来调用的；
  这个接口本身是公开仓库自己定义、自己实现的，rly0-core 只是这个接口在运行时的一种可选实现。

## 没有 rly0-core 时的降级行为

公开仓库在**完全不安装 rly0-core** 的情况下，依然可以正常编译、安装、运行：

- 启动时会检测 rly0-core 是否可用（`rly0CoreStatus` / `core/hello`）；检测失败或超时不会导致应用崩溃或阻塞其他功能。
- 多账号保存/切换、额度读取、中转注入等相关界面区域，会显示统一的提示文案“需要 RLY/0 Core”（英文版为
  “Requires RLY/0 core”），对应按钮禁用或隐藏，不会抛出未处理的错误。
- 仪表盘、线程管理、MCP 管理、Skills 管理、维护工具、外观设置等其余功能，**不依赖 rly0-core**，
  在它缺失时行为不受任何影响。

## 为什么这符合 LGPL-3.0

LGPL-3.0 允许在 Library（即本仓库以 LGPL 发布的代码）之外，存在不受 LGPL 约束的 Application 代码，
只要二者的结合方式不构成“静态或动态链接”意义上的 Combined Work，或者满足 LGPL 第 4 条对 Combined Work
的附加条件（提供可重新链接的机制、附带许可证文本等）。本仓库采用的架构进一步简化了这一点：

1. **rly0-core 不是一个库（Library），而是一个独立的可执行程序**：它有自己的进程空间、自己的内存、
   自己的生命周期，不与本仓库的任何二进制或库文件进行链接（无论静态还是动态）。
2. **通信方式是进程间通信（IPC，具体为 stdio 上的行分隔 JSON-RPC）**，而不是函数调用、共享内存、
   头文件包含或动态库加载（`dlopen`/`LoadLibrary` 之类）。这与“调用一个远程服务的 HTTP/RPC 客户端”
   在法律性质上是同一类关系，而非“链接一个库”。
3. 本仓库对外发布的、以 LGPL-3.0 授权的代码，**不包含 rly0-core 的任何源码或二进制**，也不对
   rly0-core 的存在作强制要求 —— 卸载或不安装 rly0-core，公开仓库的代码本身依然完整、可编译、可运行
   （见上文“降级行为”）。
4. 因此，rly0-core 是否开源、以何种许可证发布，是一个与本仓库 LGPL-3.0 义务相互独立的问题；
   本仓库不会因为存在这样一个通过 IPC 通信的闭源伙伴进程，而对自身以 LGPL-3.0 发布的代码产生
   任何 LGPL 意义上的“传染”义务。

如果你对上述判断有不同意见，欢迎在 Issue 中具体讨论；我们会认真对待任何指出问题的反馈。
